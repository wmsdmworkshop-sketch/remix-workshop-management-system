# ADR-007: Hybrid Foreign Keys
**Status**: Approved
**Context**: We need to balance relational integrity with flexibility when referencing external or dynamic knowledge bases.
**Decision**: We implement a Hybrid Foreign Key Strategy. We enforce hard foreign keys for permanent entities (such as Employees, Vehicles, Customers, Job Cards, and Repairs) while keeping loose/soft references for dynamic models (such as Knowledge Objects, Learning Notes, and Service Circulars).
**Alternatives**: Strict constraints everywhere (prevents schema flexibility) or loose constraints everywhere (leads to orphaned database records).
**Consequences**: Maintained relational integrity for core entities while allowing flexible expansion of knowledge bases.
